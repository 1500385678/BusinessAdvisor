## 核心原则(项目哲学)

1. **可入库优于可运行** — Phase 0 阶段宁可多写 1 篇文档 / 多勾 1 个 checkbox,也不在没有内容的"空骨架"上跑通。空骨架是负债,有内容但 UI 丑是资产。
2. **1 天 1 commit · 无半成品** — 单次开发周期必须闭环:产出 → 勾选 → commit → push,中间不留 staged 但未 commit 的"半成品树"(0828 T4 漏 commit 14h 是反面教材,已写进 `.Workflow/00_项目工作流.md` 验收清单)。
3. **三件套驱动** — 任何功能交付必须同时具备「哲学(为什么)+ 方法(怎么做)+ 案例(谁做过)」,缺一不可;这是与"普通 AI 问答"的核心差异。
4. **资产层先行** — 数据(md / JSON / PostgreSQL)决定上限,工程(API / UI)只决定下限;Phase 0-1 的瓶颈在内容,不在代码。
5. **顾问团队对齐** — 36 个行业顾问 + 12 个跨职能顾问的产物格式、commit 规范、目录命名、巡检纪律统一;本项目不是孤岛,任何"自定义规则"必须能映射到顾问团队公约(见 `~/Mac/Profits/_ConsultantLib/`)。
