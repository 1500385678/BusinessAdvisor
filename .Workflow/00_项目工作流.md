# 00_项目工作流 · BusinessAdvisor

> 本仓库项目层工作流,与 agent 层 `.Workflow/AGENTS.md` 区分。  
> 项目代号:BusinessAdvisor · 维护:24-经营-Business · 张勇 · 起始:2026-08-28

## 设计原则

- **1 天 1 commit,简洁可入库**:每个 cron 周期(02:50 巡检 / 03:50 开发)落地 1 个原子变更,无半成品 commit。
- **commit 即文档**:commit 信息遵循 `<type>: <scope> <summary>` 格式,可在 `git log --oneline` 一眼读懂一周进展。
- **巡检 + 开发分离**:02:50 巡检只读 + 报告,不修改源码;03:50 开发只写 + commit,不混巡检结论。
- **plan 即任务清单**:`.plan/YYYYMMDD.md` 是每日开发的"工单",写完即落地,push 后删除,不留垃圾。

## Commit 规范

**格式**:`<type>: <scope> YYYYMMDD · <summary>`

| type | 用途 | 示例 |
| --- | --- | --- |
| `plan` | 主计划 / Phase checkbox / 立项文档入库 | `plan: 经营 20260826 · T1 大计划入库` |
| `inspect` | 巡检报告(02:50) | `inspect: 经营 20260828` |
| `docs` | README / 注释 / 工作流 / 核心信息 | `docs: 经营 20260827 · T5 README 扩版` |
| `feat` | 新功能 / 新 API / 新页面 | `feat: 经营 20260829 · FastAPI /healthz` |
| `fix` | bug 修复 | `fix: 经营 YYYYMMDD · <bug 简述>` |
| `chore` | 配置 / 依赖 / 工具链 | `chore: 经营 YYYYMMDD · .gitignore 补全` |
| `refactor` | 重构(无功能变化) | `refactor: 经营 YYYYMMDD · <scope>` |

**scope** 固定为 `经营`(`24-经营-Business` 的中文短名),便于多仓库 grep。

## 分支策略

- **主干开发**:`main` 分支即生产可用分支,所有 cron 自动 push 的 commit 直接落在 main。
- **不开 dev / feature 分支**:单人单仓库项目,主分支开发成本最低;若 Phase 2 引入多人协作,再开 `feat/<name>` 分支。
- **强制 push**:`git push -f` 是允许的(单人仓库无协作冲突),但需在 commit 信息里标注 `(force)` 字段。

## T1-T5 任务定义(每日 03:50 一次性串行)

| 任务 | 动作 | 产物 | 时间盒 |
| --- | --- | --- | --- |
| **T1** 拉 issues | 读主计划 + `项目开发计划.md`,生成当日 plan | `.plan/YYYYMMDD.md` | ~5 min |
| **T2** 改 bug | 巡检报告里的"阻塞 / 下一步"转化为代码 fix | 1 个 commit | ~10 min |
| **T3** 加 API | 按 Phase 1 任务清单推进接口/页面 | 1 个 commit | ~10 min |
| **T4** 优化 | refactor / 文档 / 配置 / 工作流 | 1 个 commit | ~10 min |
| **T5** 推 release | README / 巡检纪律 / checkbox 收尾 | 1 个 commit | ~5 min |

注:5 个任务不会每天都全跑完(冷启动期常见 1-2 个 commit),按当日 plan 决定。

## 巡检纪律(02:50 自动化)

- 5 项巡检项:commit 数 / Phase 进度 / 跨阶段基础设施 / 脏标记 / 仓库完整性
- 巡检日报落 `.Log/巡检-经营-YYYYMMDD.md`,仅读不写源码
- 触发"连续 N 日 0 推进"告警时,在日报中显式标注,连续 3 日升级为"持续无推进"严重告警
- 脏标记(如 `.plan/*.md deleted` 未提交)持续 ≥2 日,建议 T5 决定 commit 删除 / 还原 / 加 .gitignore

## 验收清单(每个 commit 前自查)

- [ ] commit 信息符合 `<type>: <scope> YYYYMMDD · <summary>` 格式
- [ ] 只改当日 plan 涉及的文件,无顺带修改
- [ ] `项目开发计划.md` checkbox 同步更新(本仓库核心纪律)
- [ ] 无敏感信息(`.env` / `*.key` / `id_rsa` 已在 `.gitignore`)
- [ ] `git status` 干净(无未跟踪意外文件)
